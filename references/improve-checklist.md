# Skill Improve — 参考检查清单

> 同步提示：下方「每轮改进前自检」与 `skill-improve.md` 的「思维检查清单」同源，**改一处需同步另一处**，避免漂移。

## 每轮改进前自检

- [ ] 我先判过路径了吗？（能说出「哪个输入 → 哪个错误输出」→ 直接 FIX，别跑五步循环）
- [ ] 我是在修真实观察到的问题，还是在凭直觉"优化"？
- [ ] 这轮改动能被具体的 prompt 验证吗？
- [ ] 我是不是在同时改太多东西？（一次只改一件事）
- [ ] 我是在给 agent 解释 why，还是在堆 MUST/NEVER？
- [ ] 这个改动是通用的（覆盖未来新 prompt），还是只在拟合当前测试集？
- [ ] 我有没有删掉不起作用的旧指令？（skill 应该越改越精炼，不是越改越长）
- [ ] 我跑过"使用者视角穷举自审"了吗？（站到真实使用者座位上，把毛病全挑出来、改到挑不出为止——实测最锋利的一招，详见 `references/skill-improve.md` 的「使用者视角穷举自审」）

## 改写注意事项

1. 给 agent 解释 why，而非堆砌 MUST/NEVER — agent 理解原因比记住规则更有效
2. 检查重复劳动能否抽成 script — 每次都要现写的处理逻辑，固化为 `scripts/` 脚本
3. 保持信息密度 — 删除水句（"请注意以下重要事项"之类），每句话要么推进理解要么指导行动
4. 长 skill 分层 — 核心流程压进 SKILL.md（目标 < 100 行，硬性上限 < 500 行），细节放 references/

## 收敛判断速查

| 信号 | 含义 | 行动 |
|------|------|------|
| 目标模式问题消失 | 改进有效 | 下一轮 |
| 问题减轻但没消失 | 力度不够 | 同模式再改一轮 |
| 出现新问题 | 副作用 | 回滚/调整 |
| 连续 2 轮新问题=0 | 收敛完成 | 停 |
| 修正量不降反升 | 遗漏系统问题 | 重新分析 |

## 何时必须停止

- 用户说"可以了"
- 连续两轮没有新模式
- 用户说"差不多了"、"够用了"
- 新问题数为 0，且目标模式命中数已归零（WorkBuddy 无评分器，用这两个可数指标，勿用「分数 Δ」）
- 宣布收敛前，建议先跑一遍"使用者视角穷举自审"（见 `skill-improve.md`），把作者盲区型残留揪出来再收尾

## 不收敛诊断（3轮后仍无改善）

1. **skill 职责太宽** — 一个 skill 试图覆盖太多场景 → 拆分
2. **测试 prompt 矛盾** — 不同 prompt 对 skill 的期望互相冲突 → 与用户对齐
3. **底层能力限制** — 任务超出模型能力 → 诚实告知
